# CBT Module Audit — Working Findings

## Confirmed architecture

The CBT module has a school-scoped question bank, approved-question snapshots, class/subject assessments, timed student attempts, autosaved answers, automatic objective scoring, and a link to `ResultSubmission` plus `AssessmentStructure`. CBT scores are intended to flow into the official result-computation service and only become visible after official approval and publication.

## Confirmed defects

1. CBT assessment creation uses `firstOrCreate` for assessment structures by the school and title. Reusing a title can silently reuse the wrong maximum marks or weight configuration.

2. Assessment creation allows selected questions from different subjects even though the assessment has one subject. That can create invalid question papers and incorrect official subject results.

3. CBT assessment publication does not verify that its linked official result submission is still editable. A test can be published after the result submission has been approved or locked.

4. A CBT attempt writes one component through `ResultEntryService`. The result-entry service currently deletes every component not present in that one payload, so a CBT score can erase existing CA or examination components for the same subject.

5. Answer submission accepts arbitrary answer strings instead of requiring the selected answer to be one of the snapshotted options.

6. Attempt start and submit operations are not transactionally locked. Concurrent requests can race on attempt numbers or score the same attempt twice.

7. Students who have remaining attempts are displayed as completed by the frontend after the first submitted attempt, even though the backend permits another attempt.

8. CBT result review can be requested while the assessment is still open, and it does not enforce a deliberate close-before-review lifecycle.

9. Student CBT result checks omit explicit school predicates on official results and report cards, even though the attempt itself is school-scoped.

10. CBT result weights are not checked against the school’s assessment-weight budget, so active component percentages can exceed 100 and produce totals inconsistent with the result-computation model.

11. Deleting a question already snapshotted into an assessment can destroy or invalidate the assessment question paper. Referenced questions need protection from deletion.

## Repairs implemented

CBT assessment creation now enforces subject-consistent approved questions, validates the school’s active assessment-weight budget, creates a distinct assessment structure for each assessment, and refuses publication when the linked official submission is locked. The lifecycle is now draft → published → closed → results review → official approval → final publication.

Answer payloads are restricted to snapshotted options. Attempt creation uses a database lock, persists a stable shuffled question order, and respects the maximum-attempt limit. Submission scoring is idempotent under concurrent requests. Retakes now synchronize the student’s best submitted attempt to the official result, and CBT component synchronization preserves existing CA and examination components instead of deleting them.

Student result visibility now includes explicit school predicates. Students see remaining attempts accurately, can resume an in-progress attempt, and are not incorrectly blocked after a first submission when retakes remain. Question-bank deletion is blocked once a question has been snapshotted into an assessment. Active assessment structures cannot exceed 100% collectively and cannot be deactivated or deleted while dependent result or CBT records exist.

## Validation evidence

All backend PHP files, routes, tests, and migrations passed syntax checks. Laravel tests passed with five assertions. CBT assessment and question-bank routes were registered with the expected endpoint set and the student assessment routes retain the student-portal permission boundary. The frontend production build passed; the existing Vite bundle-size warning remains non-blocking. Database-backed CBT integration tests still require the target MySQL/Railway database.
