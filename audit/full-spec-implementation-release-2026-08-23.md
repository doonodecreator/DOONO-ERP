# DOONO De Creator ERP — Full Specification Implementation Release

**Release date:** 23 August 2026

This release applies the supplied Part 1 and Part 2 product guides to the canonical Laravel 13 + Sanctum backend and React/Vite frontend without replacing the existing organization → school → scoped-role architecture.

## Included in this release

The release includes the existing school ERP modules and the new specification-backed hardening slices: `CurrentContextService` is the only school-context resolver used by affected controllers and FormRequests; Support Centre ticket messages hide internal notes from non-super-admin users; centralized tenant-scoped notifications are stored in `app_notifications`; published school communications fan out to recipients idempotently; users can control global and active-school notification preferences; the notification bell reads and clears the central notification feed; and authorized leadership now has School Insights with transparent attendance and published-result summaries, persisted human-review alerts, and acknowledge/resolve/reopen actions. Timetables now support collision checks and a draft → submit → approve → publish lifecycle. Assignments now support school-scoped teacher and student file uploads through protected authenticated download endpoints. Parent and student portals use safe school/current-enrollment scopes, student CSV export is permission-aware and audit logged, and staff suspension or termination revokes active Sanctum tokens. Subscription payments now record gateway event IDs, verified timestamps, and reconciliation states to short-circuit duplicate webhook delivery. Platform owners have a real tenant-aware Feature Flags workspace with staged rollout and audited scope overrides. Global request IDs and security response headers are attached by middleware. Attendance writes now preserve immutable before/after correction records with an explanation and school-scoped audit event; the class register exposes saved attendance IDs and an expandable history view. Student 360 remains school-scoped and permission-filtered. CBT final-publication controls now match the backend submitted-results state, so the authorized workflow can proceed instead of hiding the action. School Insights calculations now run through a shared school-scoped metrics service, with idempotent daily snapshots, a paginated history endpoint, a scheduled capture command, and a mobile trend table. Authorized result reopening now requires a reason, persists the reopener and timestamp, and writes a before/after status snapshot to the school audit trail. Absent attendance records can create one preference-aware, deduplicated in-app notification for each linked parent portal user. Library catalog and loan handling now enforce active-school and active-student scope, lock inventory during issue/return transitions, retain loan history, and expose a shared mobile workflow. Library reservations now have duplicate-pending protection, fulfillment/cancellation transitions, and audited school-scoped history. School health now supports audited medical profiles, emergency flags, referrals, follow-up dates, and retention-safe clinic history. Transport now supports ordered school-scoped stops, audited vehicle inspections, automatic maintenance status on failed inspections, and a shared mobile operations workflow. Transport route creation now correctly permits an intentionally unassigned vehicle. Payroll now has school-scoped effective-dated staff contracts, active-staff options, a shared contract-entry workflow, and contract-linked gross calculation from base salary plus persisted allowances; manual gross entry remains available when no contract is selected. Profile Settings now exposes active Sanctum sessions with individual and sign-out-other-session controls. Student Portal Library now loads only the authenticated learner’s current-school books and loans and can create school-scoped reservations without exposing the staff library workspace. Support Centre now accepts size/type-validated attachments into a private disk, serves them only through visibility-checked authenticated downloads, displays SLA resolution targets, provides super-admin canned-reply options, and schedules `support:mark-sla-breaches` every fifteen minutes with overlap protection and audit events. Health access now distinguishes `view_health_records` summaries from `view_sensitive_health` clinical details; leadership can see masked emergency/referral indicators while the proprietor and nurse retain sensitive clinical access, and Nurse Dashboard rendering follows the same boundary. Asset management now has school-scoped options, history, and lifecycle-transition routes; lifecycle actions run under a row lock, validate the state machine, store immutable before/after snapshots, write audit events, and are available from mobile Asset Register controls. Direct status editing and destructive deletion are not exposed.

The guide and Support Centre contain role-aware beginner explanations, prerequisites, next actions, common mistakes, FAQs, recovery guidance, and support-ticket access. Published report cards receive opaque verification tokens and a public minimal verification page that does not expose guardian or medical data. The architecture matrix records every Part 1 and Part 2 requirement as implemented, partial, incomplete, deferred, or requiring a future architectural change.

## Safety boundaries

This build does not claim that future AI, forecasting, marketplace, OAuth, broader public API resources, webhooks, general offline mutation queues, automated backups, external SMS/push delivery, or cross-school benchmarking are complete. Those items require separate data contracts, privacy controls, consent, retries, auditability, and operational validation. Limited school-scoped read-only API keys and in-app delivery state are implemented and documented; they are not substitutes for those deferred capabilities.

## Required application steps

After extraction, run the pending migrations, clear Laravel caches, install frontend dependencies, and create a production frontend build. The notification, preference, feature-flag, payment-reconciliation, assignment-attachment, `view_insights`, School Insights snapshot, and asset lifecycle migrations are included and are safe to run with `php artisan migrate --force`; the snapshot and asset migrations use explicit short MySQL-safe index names, and already-applied migrations are skipped by Laravel.

## Phase-4 completion record — 23 August 2026

The security and operations tranche now includes MFA/TOTP login challenges with encrypted recovery-code storage and one-time recovery-code display; active-session management remains available in Profile Settings. It also adds school-scoped API keys with one-way hashes, visible prefixes, named read scopes, expiry, revocation, last-use metadata, rate-limited school/student/fee reads, one-time secret display, a Proprietor-only management page, and an administrator-facing API contract at `audit/school-api-key-contract.md`. The public contract is intentionally read-only and tenant-bound; OAuth, write APIs, webhooks, and cross-school resources are not claimed.

School communications now persist the actual internal notification outcome (`sending`, `delivered`, `no_recipients`, `failed`, or `not_sent`), recipient count, attempt/completion timestamps, and bounded failure detail. This records in-app fan-out only; no SMS, push, or external email delivery is represented as successful. Invitation creation now applies a fail-closed backend role-authority matrix so a user cannot invite a role at or above their effective school authority, while Form Teacher class/stream validation remains enforced.

The invoice hardening slice includes `dono:backfill-student-fee-invoices --dry-run` for inspection and `dono:backfill-student-fee-invoices` for an idempotent repair of legacy school IDs and invoice numbers. It derives school identity from the enrollment and student records, skips inconsistent evidence, locks each school’s settings sequence, avoids invoice collisions, and leaves immutable invoice metadata out of ordinary update paths. This command must be run against a backed-up deployed database after the invoice migrations; the sandbox has no usable MySQL test database and therefore cannot perform the data repair here.

Validation after this tranche passed full canonical PHP lint, API route and command discovery, `CACHE_STORE=array php artisan schedule:list`, the Laravel suite (12 tests, 16 assertions), service-worker/offline-queue syntax checks, the Vite production build (269 modules), the DOONO architecture guard, and `git diff --check`. ## Phase-5 completion record — 23 August 2026

The offline CBT path now has a real conflict contract. Queued answers remain account-scoped, receive stable idempotency keys during replay, carry a client-change timestamp, and are checked transactionally against the existing server answer timestamp. A stale replay receives a `409` response containing the server answer and remains retained locally for review; it is not silently discarded or allowed to overwrite a newer server value. This is intentionally limited to CBT answers; general offline mutation caching is not enabled.

Platform health diagnostics now include pending and failed database-queue counts when the corresponding tables exist, plus an explicit queue-worker heartbeat status. A configured queue driver alone is not treated as proof that a worker is alive. The production runbook records worker/scheduler requirements and states that encrypted automated backups, persistent media backups, retention, restore drills, and RPO/RTO targets require a selected deployment provider and operational verification; the source archive is not a production backup.

## Remaining-capabilities foundation record — 23 August 2026

The next tranche adds a tenant-bound OAuth client-credentials integration alongside Sanctum, with short-lived tokens, explicit read/write scopes, Proprietor-only client management, one-time secret display, revocation and expiry metadata, client-identity rate limiting, and an idempotent attendance synchronization endpoint. OAuth authorization-code/user-delegation flows are intentionally not enabled because the product still uses Sanctum for first-party browser/mobile authentication and has no approved external identity-provider contract.

External communication now has real provider adapters for Twilio SMS and Firebase Cloud Messaging. Push tokens are registered and revoked by authenticated users, stored encrypted with hash-based deduplication, and delivery attempts are retained per recipient. Twilio status callbacks require the documented signature and apply monotonic state transitions. Provider credentials remain server-side and unconfigured providers fail closed; queued/provider-accepted states are not represented as delivered.

The backup foundation adds an auditable `dono:backup` command that validates GPG and database-dump binaries, creates a transaction-safe database dump, encrypts it with AES-256 symmetric GPG encryption, uploads only the encrypted artifact to a configured private disk, records a checksum and run status, removes plaintext work files, and supports an explicitly enabled daily scheduler plus a platform-owner queued manual trigger. Production media backup, retention, restore drills, and measured RPO/RTO targets remain deployment-dependent.

Offline support now includes attendance registers in addition to CBT answers. Attendance class-list responses expose the saved attendance timestamp; register submissions carry that timestamp, use stable idempotency keys, and return a `409` conflict when a newer server version exists. The browser queue is account-scoped and retains unresolved conflicts. Arbitrary non-GET API mutations remain intentionally uncached.

The marketplace foundation lets Software Owners publish, disable, and retire approved catalogue entries, while school Proprietors install or revoke school-scoped entries with encrypted configuration storage and audit history. Installation does not grant arbitrary executable plugin access. Benchmarking is opt-in and revocable; only consented schools with existing insight snapshots contribute to an identity-free aggregate, and output is withheld below a minimum cohort of five schools.

Performance evidence now includes a read-only HTTPS load-test harness reporting status counts, failure rate, throughput, and p50/p95/p99 latency, plus global request IDs, response timing headers, and bounded slow-request logs. No extreme-scale capacity claim is made from local validation; deployment-specific load evidence is still required.

Validation for the tranche passed full canonical PHP lint, route and command discovery, scheduler listing, the Vite production build, the architecture guard, offline/service-worker syntax checks, and `git diff --check`. Database-backed OAuth, provider callback, tenant, marketplace, benchmark, backup, attendance-conflict, payment, and cross-school tests remain required in deployed CI because the sandbox has no usable MySQL test database or SQLite driver.
