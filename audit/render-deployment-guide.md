# DOONO De Creator ERP — Render Deployment Guide

## Service architecture

The repository uses the canonical Laravel application under `backend/dono-api` and the React application under `frontend`.

| Render resource | Purpose | Required configuration |
|---|---|---|
| `dono-api` web service | Laravel API and health endpoint | Docker runtime, `/up` health check, `php artisan migrate --force` before deploy |
| `dono-frontend` static site | React/Vite browser application | Build `cd frontend && npm ci && npm run build`; publish `frontend/dist`; rewrite all routes to `/index.html` |
| `dono-db` Postgres | Persistent application database | Same Render region as backend; `DB_URL` is injected from its connection string |
| `dono-worker` background worker | Queued mail, reports, and asynchronous tasks | `php artisan queue:work ...`; shares `APP_KEY`, database, mail, and storage settings with the web service |
| `dono-subscription-expiry` cron | Hourly subscription expiry processing | `php artisan subscriptions:expire` |
| `dono-subscription-reminders` cron | Daily renewal reminders | `php artisan subscriptions:reminders` |

Render’s Blueprint specification supports web services, static sites, workers, cron jobs, and Postgres databases in one `render.yaml`. Render Postgres provides an internal connection string for services in the same region. Static sites support global CDN delivery and SPA rewrite rules. Cron schedules use UTC.

## Required environment values

Render prompts for every `sync: false` value. Set them before the first production deploy.

| Variable | Value |
|---|---|
| `APP_URL` | Public URL of the Laravel API, for example `https://dono-api.onrender.com` |
| `FRONTEND_URL` | Public URL of the Render static site, for example `https://dono-frontend.onrender.com` |
| `CORS_ALLOWED_ORIGINS` | Exactly the frontend URL; do not include a trailing slash |
| `PAYSTACK_PUBLIC_KEY` | Paystack public test or live key matching the environment |
| `PAYSTACK_SECRET_KEY` | Paystack secret test or live key matching the environment |
| `MAIL_HOST`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM_ADDRESS` | SMTP provider values for real email delivery |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_DEFAULT_REGION`, `AWS_BUCKET` | S3-compatible persistent storage values |
| `AWS_ENDPOINT` and `AWS_URL` | Set these when using a non-AWS S3-compatible provider |
| `VITE_API_URL` | `https://dono-api.onrender.com/api/v1` for the static frontend |

`APP_KEY` is generated by Render and shared with the worker and cron services. Never regenerate it after deployment. Changing it invalidates encrypted data and existing signed links.

## Database note

This Blueprint uses Render Postgres because Render provides managed Postgres as its native relational database service. The Laravel configuration supports `DB_CONNECTION=pgsql` and a `DB_URL` connection string. The deployment image includes both `pdo_pgsql` and `pdo_mysql`.

If the existing production database is MySQL, do not point the new deployment at it as PostgreSQL. Either migrate the data and verify every migration/query on PostgreSQL, or keep the existing MySQL database hosted by an external provider and change the Blueprint environment values to `DB_CONNECTION=mysql` plus the provider’s connection variables. A production database migration must be backed up and rehearsed before cutover.

## Storage note

Render service filesystems are not a durable media store for school logos, profile photos, report-card assets, or uploaded documents. The Blueprint sets `FILESYSTEM_DISK=s3`; configure the S3-compatible variables before allowing uploads. Do not use the local `public` disk for production persistence.

## First deployment checks

After the Blueprint finishes, open the backend `/up` URL and confirm a healthy response. Open the frontend URL and confirm the browser can call `/api/v1` through the configured `VITE_API_URL`. Register a test account, verify its email, log in, create a school, and confirm that a second school cannot access the first school’s records. Then perform one Paystack test payment, verify that the transaction and subscription update, and test one duplicate verification request.

Use a separate Render worker service. A web service alone does not process queued email. Cron jobs must remain enabled for subscription expiry and reminder processing. Monitor Render logs for failed jobs and configure a backup/restore procedure for the database and object storage before onboarding real schools.
