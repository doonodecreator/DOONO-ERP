# DOONO ERP Readiness Audit Findings

## Inventory baseline

- Frontend contains 20 role-dashboard files: Platform Owner, Organization Owner, Proprietor, Principal, Vice Principal Academic, Vice Principal Administration, Nursery Head, Primary Headmaster, Secondary Principal, Teacher, Form Teacher, Cashier/Bursar, Accountant, Librarian, Nurse, Hostel, Transport, Reception, plus generic Dashboard and portal files.
- Frontend contains 108 page components.
- Backend exposes 229 API route declarations and 106 API controllers.
- Frontend build configuration uses one canonical Axios client with `/api/v1` in the base URL.

## Confirmed architectural findings

1. Subscription-plan, school-subscription, coupon, promo-campaign, currency, feature, system-setting, platform-announcement, and platform-owner operations are inside a `role:super_admin` route group for write operations. Public plan reads are outside that group.
2. Organization ownership checks are implemented through CurrentContextService.
3. School CRUD routes are authenticated but store/update/delete authorization is partly implemented in SchoolController rather than route middleware. SchoolController `store` currently resolves the current organization without an explicit owner/platform-role guard; this needs hardening.
4. Many role dashboards contain panels that say `Opening the registered ... workspace` instead of rendering a real module. These are confirmed placeholders and conflict with the requirement that every button lead to a working workflow.
5. The generic and many role-specific dashboard controllers do not return communication data. A shared Navbar school-notice inbox was added in the previous repair, but dashboard-specific communication sections remain inconsistent.
6. PaymentController contains an older public fee-payment verification method and a public Paystack webhook. The webhook is signature-verified; the fee verification endpoint is not school/user scoped and should be reviewed against current frontend usage before hardening.
7. Subscription initialization includes pending-payment reuse, amount/currency checks, Paystack verification, and trial-aware activation, but requires targeted tests for duplicate webhook delivery, renewal after expiry, renewal during trial, and failed checkout cleanup.
8. Frontend static scan found no remaining obvious `user?.role || user?.roles` role-detection violations, and no duplicate `/v1` API path usage in source.

## Verified repairs applied during the audit

- School creation now requires Software Owner or Organization Owner authority; school deletion is limited to Software Owner or the owning Organization Owner, and deletion is logged.
- Added a durable `fee_payment_transactions` ledger with unique Paystack references, school/fee scoping, status, gateway response, and idempotent settlement support.
- Replaced the broken legacy fee-payment Paystack path that queried nonexistent `fee_payments` columns. Fee checkout now resolves the current `StudentFee`, verifies school ownership and outstanding balance, reuses pending checkout, validates gateway amount, and records the current `FeePayment`/receipt through `PaymentService` exactly once.
- Moved fee-payment initialization and verification into the authenticated school/subscription middleware group; the old public verifier route was removed.
- Parent fee breakdowns now include exact student-fee identifiers; the parent Pay button opens the real Paystack payment modal instead of being unbound.
- Student and parent portal responses now return school-scoped published notices; the student portal renders a School Notices section.
- Focused PHP lint, route inspection, backend tests, and the Vite production build passed. The Vite build still reports a bundle-size warning, not a compilation failure.

## Final repair pass evidence — 21 August 2026

- Added the missing `library` page case in `App.jsx`; role dashboards now resolve that target to a real workspace. Students are routed to a separate `StudentLibrary` page rather than the librarian management workspace.
- Added `GET /student/library` under `auth:sanctum`, `has.school`, `password.changed`, `subscription`, and `portal_student_access`. The response is restricted to the authenticated student’s school catalogue and personal loans; it does not expose schoolwide members, loans, fines, or management records.
- Added guarded outstanding-fee data to the student portal and created a role-aware `PortalFees` page for students and parents. Their fee navigation no longer calls staff-only fee configuration endpoints, and each Pay button preserves the exact `student_fee_id`, student, and fee-category identifiers.
- Corrected the Paystack fee callback from `/fees-payments` to `/payment-callback`. The callback page now verifies through the authenticated, school-scoped verifier. The legacy `/fees-payments` URL redirects to the authenticated application root instead of rendering an incomplete callback or shell.
- Migrated `FeePaymentModal` from Bootstrap-only markup to the shared `Modal`, `Button`, and `Alert` components.
- Changed linked-module tab handlers in Form Teacher, Nursery Head, Primary Headmaster, Secondary Principal, Student, and Vice Principal Academic dashboards so they navigate directly to the real App page without rendering a placeholder frame first.
- Static checks returned no unresolved Sidebar page targets after alias resolution, no obvious legacy role-detection expressions, no duplicate `/v1` paths, and no `currentSchoolId()` calls.
- Verbose route inspection confirmed fee initialization and verification are under `auth:sanctum`, `has.school`, password-change, and active-subscription middleware. Communication routes are under the same school and subscription boundary with separate view/send permissions. Subscription-plan, coupon, promo-campaign, and school-subscription routes are protected by `role:super_admin`.
- PHP lint, the two existing Laravel tests, `git diff --check`, and repeated Vite production builds passed. Vite continues to report only a bundle-size warning. Migration-status validation could not connect in this sandbox because no MySQL socket/database environment is configured; this remains an environment-deployment check for Termux/Railway.
