# DOONO Buttons and Forms Audit — Final Findings

## Scope

The frontend contains 110 page components plus shared layout, feedback, table, modal, dashboard, form, and navigation components. The audit covered native buttons, shared buttons, modal actions, table actions, form submits, inputs, selects, textareas, loading states, validation states, and mobile sticky form actions.

## Confirmed weaknesses

The codebase had several control systems in parallel: shared `Button` and `FormField` primitives, legacy inline-styled controls, Tailwind-style controls, and browser-default native controls. A static audit found 278 button openings without a class and many raw form controls. Several interactive buttons had no explicit type, creating a risk that a navigation or dismiss action inside a form could submit the form unexpectedly. The first-school setup, organization creation, and add-parent pages were major form outliers with inline styling, inconsistent error handling, and inconsistent action spacing. The parent form also sent a hardcoded `school_id: 1`.

The Promotions page contained a visible Delete button with no handler, so it did not perform the action its label promised.

## Repairs implemented

A global control-normalization stylesheet now gives legacy native buttons and unclassed inputs, selects, and textareas consistent minimum heights, borders, radii, typography, focus states, invalid states, and disabled behavior while preserving intentional class-based variants. The shared `Button` primitive now supports reliable loading semantics, `aria-busy`, protected disabled state, loading text, focus styles, and primary, secondary, success, danger, warning, outline, ghost, and link variants. Shared form actions are footer-safe on mobile and keep touch targets consistent.

The Organizations page now uses `Button`, `FormField`, `FormActions`, `SectionCard`, `Alert`, and `DataTable` with inline status errors instead of browser alerts and inline form styling. AddSchool now uses shared fields, alerts, buttons, and actions while preserving country loading and onboarding behavior. AddParent now uses grouped shared fields and actions, removes the hardcoded school id, and replaces browser alerts with visible error state and consistent navigation.

A safe codemod added explicit `type="button"` to interactive onClick controls and `type="submit"` to remaining disabled save controls. The static audit now reports zero JSX button openings without an explicit type. Promotions Delete is now confirmation-protected, calls the verified `DELETE /promotions/{id}` endpoint, refreshes the list, and displays an error if the action fails.

## Validation evidence

The frontend production build passed after all changes, `git diff --check` passed, and the static audit confirmed zero buttons missing explicit types across the frontend source. The Vite bundle-size warning remains non-blocking. A visual phone pass remains recommended for the highest-traffic legacy pages, especially Subscriptions, Settings, Role Invitations, CBT authoring, and financial workflows, because those pages still contain large Tailwind/native control regions that are functionally wired but should be progressively migrated to the shared primitives in future UI passes.
